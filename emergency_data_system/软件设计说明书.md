# 应急数据清洗与可视化系统 — 软件设计说明书

> **版本：** v1.0  
> **日期：** 2026-07-29  
> **开发环境：** Python 3.11+ / Flask 3.x / Pandas 2.x / SQLAlchemy 2.x  
> **运行环境：** Windows / Linux / macOS，支持 Docker 容器化部署

---

## 一、软件概述

### 1.1 软件名称
应急数据清洗与可视化系统（Emergency Data Cleaning & Visualization System）

### 1.2 软件定位
面向基层应急管理部门的轻量化 Excel 数据治理工具，实现多源零散报表的自动清洗、标准化、可视化分析与合规导出。

### 1.3 目标用户
- 区县级、乡镇级应急管理局工作人员
- 安全生产监管科室日常办公人员
- 需处理安全生产检查、隐患排查、企业备案等 Excel 报表的政务人员

### 1.4 运行模式
B/S 架构（浏览器/服务器），单机或局域网部署，用户通过浏览器访问操作界面。

## 二、技术架构

### 2.1 整体架构

系统采用三层分层架构：

```
┌─────────────────────────────────┐
│  前端展示层                      │
│  HTML5 / CSS3 / JavaScript      │
│  ECharts 5.x 可视化引擎          │
│  文件上传 · 统计卡片 · 图表 · 日志  │
├─────────────────────────────────┤
│  后端服务层                      │
│  Flask 3.x Web 框架             │
│  Jinja2 模板引擎                │
│  RESTful API（10 个端点）         │
├─────────────────────────────────┤
│  数据处理层                      │
│  Pandas 2.x 数据清洗引擎         │
│  OpenPyXL Excel 读写             │
│  SQLAlchemy ORM 持久化           │
└─────────────────────────────────┘
```

### 2.2 技术栈

| 层级 | 技术 | 版本 | 用途 |
|------|------|------|------|
| 后端框架 | Flask | 3.x | Web 服务、路由管理 |
| 模板引擎 | Jinja2 | 3.x | 服务端页面渲染 |
| 数据处理 | Pandas | 2.x | Excel 解析、清洗、统计 |
| Excel 操作 | OpenPyXL | 3.x | Excel 读写、样式格式化 |
| 数据库 ORM | SQLAlchemy | 2.x | 数据持久化、查询 |
| 默认数据库 | SQLite | 3.x | 零配置本地存储 |
| 前端可视化 | ECharts | 5.x | 图表渲染 |
| 测试框架 | pytest | 7.x | 自动化测试 |

### 2.3 设计原则

本系统遵循 SOLID 五项设计原则：

- **单一职责（SRP）：** 清洗引擎、数据库、认证、报表导出各自独立模块
- **开闭原则（OCP）：** 清洗规则通过 config.py 扩展，无需修改核心逻辑
- **里氏替换（LSP）：** 数据模型统一继承 SQLAlchemy Base 基类
- **接口隔离（ISP）：** 10 个 API 端点各自独立，职责单一
- **依赖倒置（DIP）：** 高层模块依赖抽象配置而非具体实现

## 三、模块设计

### 3.1 模块总览

| 模块 | 文件 | 职责 |
|------|------|------|
| 清洗引擎 | data_cleaner.py | Excel 读取、字段标准化、格式校验、去重填充、异常日志 |
| 系统配置 | config.py | 路径、字段映射、清洗规则、地域前缀参数 |
| Web 服务 | app.py | Flask 路由、10 个 API 端点、请求调度 |
| 数据库 | database.py | ORM 模型、CRUD 操作、统计查询 |
| 用户认证 | auth.py | 登录/注册/登出、会话管理、角色权限 |
| 报表导出 | report.py | 多 Sheet 格式化报表、橙色标注、统计汇总 |
| 前端交互 | charts.js | 文件上传、ECharts 图表渲染、历史看板 |
| 页面模板 | index.html | 系统界面结构、登录条、上传区、图表区 |

### 3.2 清洗引擎（data_cleaner.py）

核心业务模块，实现 9 步清洗流水线：

```
步骤1  读取 Excel      → load_excel()
步骤2  列名标准化       → standardize_columns()
步骤3  日期规范化       → normalize_date()
步骤4  号码校验         → clean_phone()
步骤5  名称规整         → clean_company_name()
步骤6  地址补全         → complete_address()
步骤7  去重 + 填充      → deduplicate_and_fill()
步骤8  异常日志         → collect_anomaly_logs()
步骤9  保存结果         → Excel + 日志 + 橙色标注
```

**支持的清洗规则：**
- 字段列名标准化：20+ 种字段变体映射为 5 类标准字段
- 日期格式规范化：6 种格式统一为 YYYY-MM-DD
- 联系方式校验：手机号（11 位）、固话（区号+号码）、国际号码（+86）
- 企业名称规整：去空格、统一中英文括号、空值替换
- 地址自适应补全：可配置省/市/区前缀自动拼接
- 数据去重：以"企业名称+排查日期"为核心维度
- 缺失填充：空白字段统一填充"待补充"，输出 Excel 橙色加粗标注

**异常检测类型（4 种）：**
1. 必填字段缺失——企业名称/联系电话/排查日期为空
2. 联系方式格式错误——手机号/固话格式不合法
3. 企业名称缺失——企业名称为空或无效占位符
4. 日期格式无法识别——日期字符串无法解析

### 3.3 数据库模块（database.py）

**数据模型（2 张表）：**

| 模型 | 表名 | 说明 |
|------|------|------|
| CleanRecord | clean_records | 清洗后的有效数据记录 |
| AnomalyRecord | anomaly_records | 异常日志记录 |

**CleanRecord 字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | Integer (PK) | 自增主键 |
| user_id | String(64) | 所属用户（多用户数据隔离） |
| batch_id | String(32) | 清洗批次号 |
| company_name | String(200) | 企业名称 |
| phone | String(20) | 联系电话 |
| check_date | String(10) | 排查日期 |
| address | String(500) | 企业地址 |
| check_type | String(100) | 排查类型 |
| source_file | String(200) | 原始文件名 |
| is_anomaly | Boolean | 是否异常行 |
| created_at | DateTime | 入库时间 |

**数据库选型：**
- 默认 SQLite（零配置，开发/演示环境）
- 支持 MySQL/PostgreSQL 切换（设置环境变量 DATABASE_URL）

### 3.4 用户认证模块（auth.py）

**认证机制：**
- Flask session（签名 cookie）实现用户会话
- werkzeug.security 进行密码哈希存储（scrypt 算法）
- 用户数据存储于本地 JSON 文件（users.json）
- 会话有效期 24 小时

**角色体系：**
- admin：管理员，可创建用户、查看用户列表、清理数据
- operator：操作员，可执行数据清洗和查询

**路由清单：**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | /auth/login | 用户登录 |
| POST | /auth/register | 用户注册 |
| POST | /auth/logout | 用户登出 |
| GET | /auth/status | 查询登录状态 |
| GET | /auth/users | 列出所有用户（管理员） |

### 3.5 报表导出模块（report.py）

生成多 Sheet 格式化 Excel 报表：

| Sheet | 内容 | 格式 |
|-------|------|------|
| 清洗数据 | 清洗后的完整数据表 | 深蓝表头、冻结首行、列宽自适应 |
| 异常日志 | 异常数据明细 | 异常类型颜色标签 |
| 统计汇总 | 数据质量概览 | 有效率计算、颜色区分指标 |

**样式特性：**
- 表头：深蓝色背景（#1A3A5C）+ 白色加粗字体
- "待补充"单元格：橙色加粗字体 + 浅黄背景
- 有效率：绿色大字体显示

## 五、安全设计

| 维度 | 措施 |
|------|------|
| 数据本地化 | 所有数据仅本地存储，无外网自动上传 |
| 操作可追溯 | 完整清洗日志 + 文件操作记录 |
| 权限管控 | 登录认证 + admin/operator 双角色 |
| 密码安全 | werkzeug scrypt 哈希存储 |
| 会话安全 | Flask signed cookie + 24h 有效期 |
| 路径安全 | os.path.basename 防路径穿越 |
| 文件校验 | 白名单扩展名 + 10MB 上限 |
| 最小依赖 | 无遥测、无第三方数据上传 |
